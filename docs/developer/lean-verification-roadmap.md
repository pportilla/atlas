# Lean verification roadmap for Atlas

Suppose a release of Atlas reports that $y^2$ belongs to $(x-y,x^2)$. We can check this case by writing $y^2=x^2-(x+y)(x-y)$. The proposed Lean theorem asks for a guarantee about **every valid rational ideal membership request** handled by a named release, including requests whose answer is false. Membership is a natural first case because it already has a precise mathematical specification and its native reduction code is used throughout Atlas.

This proposal uses checkout `66a47b6694a5` as its baseline. The existing kernel has written correctness arguments, consistency checks and independent comparison tests. The Lean project and the milestones below are proposed work. [Kernel algorithms and proofs](../../native/KERNEL.md) · [Public algebra operations](../reference/index.md) · [Benchmarks](../../benchmarks/README.md)

## The first public theorem

> Fix an Atlas release and a covered execution configuration. For every valid membership request over an ordered ring ℚ[x₁,…,xₙ], let F be its list of ideal generators and f its query polynomial. Whenever Atlas returns a successful Boolean b, b is true if and only if f belongs to the ideal generated by F.

Use mathlib's multivariate polynomials over ℚ and `Ideal.span` for the meaning of the request. Include both public monomial orders, exact rational coefficients, natural-number exponents, the zero ideal, the unit ideal and the scalar ring ℚ. For a prepared basis, F refers to the ideal associated with its creation. An error, timeout or stale basis reference has its own outcome. Prove termination and successful completion separately for the inputs and resource model where Atlas intends to promise them. A function that always fails satisfies the successful-answer statement vacuously. [Gröbner bases and ideal operations](../reference/ideals.md) · [Mathlib's polynomial division theory](https://leanprover-community.github.io/mathlib4_docs/Mathlib/RingTheory/MvPolynomial/Groebner.html)

## Milestones for membership

### 1. Connect one Lean theorem to production C++

Choose `Ring::divides` in the packed Gröbner engine. Given two valid packed monomials in the same ring, its Boolean must agree with componentwise comparison of their exponent vectors. Its implementation performs a loop of word-level unsigned subtractions. The proof must account for the 16-bit lanes, the unused high bit in each lane, zero padding, the ring's stride, and the bounds on each memory read. There are no external arithmetic-library calls in this routine. [Packed representation and divisibility](../../native/groebner.hpp)

Create a pinned Lean project for specification and proofs. Prototype a translation of this small C++ fragment into a program representation with defined Lean semantics. Generate it from the exact production function at build time. Document how the translation is checked and which part of the C++ frontend, if any, is trusted. A theorem about a handwritten model is an intermediate deliverable until its correspondence with the source has been established.

**Completion criterion.** A clean checkout regenerates the program representation and rechecks the universal theorem. As a negative control, temporarily change the loop to skip the last packed word. Rebuilding from that source must prevent certification against the original specification. If the tooling cannot represent this routine faithfully, test a smaller C++ fragment used by the actual routine before expanding to the reducer. The translation method is the first open engineering decision.

### 2. Prove the packed membership decision given a valid basis

Formalize what it means for a native basis handle to represent a Gröbner basis B of the input ideal in the declared order. Extend the source connection to `Engine::contains` and its `reduce_terms<true>` specialization. Show that each reduction preserves ideal membership, including primitive rescaling by a nonzero rational. Prove that reducer lookup finds an eligible divisor whenever one exists. This justifies the early `false` on the first irreducible leading term. Exhausting the terms justifies `true`. Carry these results through the C interface, where −1 denotes an error. [Reduction loop and C interface](../../native/groebner.cpp) · [Kernel representation](../../native/groebner.hpp)

**Completion criterion.** The theorem applies to every well-formed packed query and valid basis handle in scope. It lists the required integer-library, memory and calling-convention assumptions. Correct construction of the basis remains an explicit hypothesis at this milestone.

### 3. Establish the basis invariant on every CPU route

The CPU setting can select several algorithms. Prove that each constructor returns a basis that generates the **original** ideal and whose leading monomials generate the initial ideal in the requested order. These facts discharge the basis hypothesis in milestone 2.

| Production route | Proof obligation |
| --- | --- |
| Direct packed basis | Prove that insertion, discarded critical pairs, strategy changes and final reduction preserve the required basis properties. Start with fresh generators and `known=0`. [Buchberger implementation](../../native/groebner.cpp) |
| Modular reconstruction | Formalize the certification argument for homogeneous modular reconstruction. It needs a valid trace-prime basis with matching leading monomials, admissible denominators, the critical-pair checks and the reductions of the input generators. Prove both shared and sparse verification paths, followed by dehomogenization. A candidate basis of a larger ideal could pass the input reductions alone. [Correctness argument](../../native/KERNEL.md#certification) · [Modular solver](../../native/modular.cpp) · [Shared verifier](../../native/groebner_verify.hpp) |
| Hilbert-driven construction | Prove that the Hilbert data used to skip pairs is exact and that returning to the declared order yields a basis of the original ideal. [Hilbert implementation](../../native/hilbert.cpp) |
| Wide exponents and coefficients | Prove the sparse arbitrary-precision representation, its basis and division routines, including the binomial shortcut. Cover fresh solves beyond the packed variable or degree limits and queries whose reduction overflows after a packed basis was built. Prove that conversion preserves variables, order and rational coefficients. [Wide kernel](../../native/field_wide.cpp) · [Packed query fallback](../../engine/groebner.py) · [Wide basis adapter](../../engine/wide_basis.py) |

**Completion criterion.** Compose the constructor and query theorems for fresh CPU inputs. Record which configurations can reach each route. A dispatch label such as `cpu` is too broad to use as a proof hypothesis for the direct algorithm.

### 4. Prove the public call and saved-basis paths

Follow a request from the shared session, CLI or HTTP endpoint through the worker, parser and native interface, then follow the Boolean back to the caller. Specify what an accepted expression denotes, including coordinate order and exact division by rational constants. For wrappers, prove faithful transport or state it as a trust assumption and qualify the release claim accordingly. [Shared session](../../engine/session.py) · [Session operation](../../engine/session_algebra.py) · [CLI](../../engine/algebra_cli.py) · [Worker](../../engine/algebra_worker.py) · [Parser](../../engine/polynomial.py) · [Dispatcher](../../engine/algebra.py)

Three paths need specific work in this checkout.

- **Scalar ring.** For an empty variable list, Python currently decides whether the generators give the unit ideal and answers membership. Move these decisions into `native/`, preserve the public result, and prove the two cases over ℚ. [Scalar basis and membership](../../engine/algebra_groebner.py)
- **Restored bases and replay.** Restoring rows as a known Gröbner basis skips critical pairs. Prove that each trusted caller supplies rows from a valid producer in the same ring and order. HTTP references can also originate from quotient-ring results. Track their relation to the source ideal through session ownership, server storage, worker metadata and serialization. Prove that portable replay denotes that same ideal even when it supplies basis rows as fresh generators. [Restore path](../../engine/algebra_groebner.py) · [Server basis store](../../engine/algebra_basis_store.py) · [Replay](../../engine/algebra_replay.py)
- **Device and fallback paths.** Explicit GPU requests can affect basis construction and monomial membership queries. Prove that every accepted device result meets the same postcondition, including claims that a term has no divisor. Python currently assembles the retained terms and interprets an empty remainder. Move mathematical decisions into the native boundary, including the wide and compatibility paths, and prove the exact fallback. Scope release theorems to the native production configuration and name the compute modes covered. [Basis dispatch](../../engine/algebra_execution.py) · [Device remainder](../../engine/gpu_normal_form.py) · [Native host check](../../native/local_operations.cpp)

**Completion criterion.** Publish a table mapping each supported entry point, basis origin and compute mode to a theorem or an explicit outstanding obligation. A first release may cover fresh CPU requests before cached or GPU requests. Include `auto` once its reachable routes in that build are covered.

## Rechecking a release

Ship the proof sources, reviewed theorem statements and one reproducible verification command. Record the exact source tree, build configuration, target ABI, compiler and linker flags, native library versions, Lean toolchain and mathlib revision. List external contracts, such as the FLINT integer operations used by reduction. State which parser, translation and compilation steps the theorem assumes correct. Hashes identify the artifact to which the claim applies. A further compiler-correctness or translation-validation argument is needed for a machine-code guarantee independent of the C++ compiler. [Native build rules](../../native/groebner.mk) · [Example of a compiler semantic-preservation theorem](https://compcert.org/man/manual001.html)

Rebuild extracted definitions from the release tree, recheck each exported theorem, compare its statement with the reviewed specification and audit its transitive axioms. Reject unfinished proofs and unexpected axioms, including assumptions that simply assert the correctness of the Atlas routine being verified. A change to covered C++, wrappers, flags or dependencies triggers requalification of the affected claims. [Lean proof validation](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)

Keep regression and performance work alongside the proofs. Exercise fresh and restored bases, yes and no answers, constants, the packed degree boundary, intermediate overflow, and coefficients and exponents beyond machine width. Run `make check-native-boundary` when production Python changes. For a changed computation, rerun the original Atlas and Singular cases with identical inputs, orders and multiple trials, recording agreement, timings and remaining slower cases. Record proof-build time separately from user computation time. [Wide and restored-basis regressions](../../tests/test_algebra_groebner.py) · [Singular agreement](../../tests/test_algebra_groebner_singular.py) · [HTTP basis references](../../tests/test_http_basis_refs.py) · [Replay tests](../../tests/test_algebra_replay.py) · [Membership timing cases](../../benchmarks/algebra-membership-ryzen-6800h.json)

## Extending coverage across Atlas

| Next public claims | Dependency and completion criterion |
| --- | --- |
| Reduced bases, normal forms and quotient arithmetic | Reuse membership's basis theorem. Add monicity and reduced tails for the public basis, exact scale and a canonical remainder for normal form, then prove the quotient-ring representation respects equality. Elimination, intersection, saturation and ideal quotients each need their own ideal-equality theorem. [Ideal operations](../../native/ideal-algorithms.md#operations-on-ideals) |
| Factorization, decomposition and normalization | For rational factorization, prove reconstruction with multiplicities and irreducibility over the declared field. For primary decomposition, prove the intersection equals the input ideal and each component is primary with the reported associated prime. For normalization, identify each reported algebra with the integral closure in the component's fraction field. These are also dependencies of claims about geometric components. [Polynomial factors](../../native/polynomial_factors.cpp) · [Primary decomposition](../../native/primary_decomposition.cpp) · [Normalization](../../native/normalization.cpp) |
| Local algebra and field extensions | Verify the point translation, local order, units and standard-basis construction before claiming local lengths, tangent cones or multiplicities. For geometric computations over extensions of ℚ, carry the defining field, its embedding and the coordinate space through every map. [Local bases](../../native/local_basis.cpp) · [Point-local quotients](../../native/local_point_quotient.cpp) · [Marked fields](../../engine/marked_field.py) |
| Resolution of a germ | Begin with a chart family such as the identity or an ordinary blowup. Prove pullback, saturation and chart domains, then cover, overlap and gluing, and the proper birational map on the claimed germ. Prove the embedded total-transform crossings and multiplicities over the origin fibre, and the intrinsic smooth strict transform for reduced input, as separate statements. Account for native preverified returns, dedicated verifiers and Python's assembly of geometric predicates. Every successful producer must imply the theorem for its mode. Quick or exhaustive search termination is a separate question. [Resolution pipeline](../thematic/resolution-pipeline.md) · [Result assembly](../../engine/resolve.py) |
| Dual complex, zetas and saved resolutions | Prove geometric component identities and face maps, disjoint ownership of strata, their Euler characteristics, multiplicities and orders of the volume form. Then justify the zeta formulas and the link between an intrinsic record and an embedded companion for the same germ. Reconstruct or establish provenance for archived strata used in replay. Give legacy results that rely on archived data a conditional claim. Distinguish a resolved germ from completeness of its incidence or availability of its zetas. [Resolution records](../thematic/resolution-records.md) · [Archive replay](../../engine/strata.py) |

**First proposed pull request.** Deliver the pinned proof project, the specification of packed divisibility, the source translation for `Ring::divides`, the theorem and its source-mutation check. Review the mathematics and the source correspondence together. That result gives maintainers an actual cost and trust boundary on which to base the larger membership effort.
