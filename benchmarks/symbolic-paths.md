# Symbolic computation on the default CPU route

This audit used the same candidate as the resolution benchmark on 2026-11-14, fingerprint prefix `832d2556e247`. File and line numbers refer to that build. The probe traced named SymPy operations and their nearest engine callers in a fresh Python process per workload. Direct Python API fixtures construct their symbols, coefficient fields and candidates before tracing. The public resolver fixtures include imports and chart construction. The probe does not instrument child processes. The plane worker is a compiled executable and the chain producer runs through a native library. [Audit driver](symbolic_path_audit.py)

## Changes after this measurement

The table records the earlier build. The public resolver now sends sparse native values through general blowups, intrinsic gluing and projective workers. The saved-chart reader also defaults to native values when its caller has already imported SymPy. A caller that needs symbolic chart objects can request `native=False`. Missing kernel operations and unsupported number-field expressions produce errors in native mode. The number-field adapter accepts a marked exact root or coefficients in the generator's power basis.

Run the audit driver with the case name for the current native route. Add `--symbolic-inputs` to reproduce a direct caller supplying SymPy objects. The regression suite blocks imports in fresh interpreters and workers, including old marked-field records, weighted charts and a 35-coordinate projective blowup. [Current resolution pipeline](../docs/thematic/resolution-pipeline.md)

## Representation, orchestration and reference checks

- **General graph.** The curved-centre certificate for `(y-x²)²-xz²` over `(y-x²,z)` triggered none of the monitored SymPy algorithms. The marked Whitney graph retained two small expression expansions converting between a public algebraic generator and native coefficient rows at `engine/field_polynomial.py:32,117`. The modern graph's valuation and relative Jacobian run in `engine/graph_atlas.py:25`. Its symbolic minor calculation is gated by the comparison/reference modes at line 26.
- **Canonical centre and repair.** For the maximum of `(y+x²)^4+(x-z²)^6+z^11`, `engine/centres.py:462` used three expression-size counts to rank choices. For the supported three-variable Newton repair in the driver, `engine/surface.py:118` and `engine/centres.py:663` used three and five such counts. Neither calculation called a monitored symbolic polynomial algorithm. The non-affine jet loop at `engine/centres.py:239` schedules native derivatives and membership decisions at lines 184 and 191. Symbol construction, Python iteration and ranking remain on these routes.
- **Chart representation.** `engine/atlas.py:79` builds expressions from sparse terms, and line 256 serializes chart polynomials. `engine/atlas_gluing.py:387` renames chart variables for overlap tests. The two chain samples materialized four and five SymPy polynomials from already computed basis rows at `engine/groebner.py:115` during intrinsic verification. `engine/atlas_gluing.py:213` still requests these objects to traverse a basis, while the factor operation is native. Sparse row iteration removes that intermediate without changing the overlap calculation.
- **Independent comparisons.** The fraction-field elimination at `engine/geometric_components.py:415` is only reached in reference or comparison mode. The default route obtains the shape by lex elimination over the coefficient field at line 410. The archived per-engine graph-strata formulas are called by `tests/strata_oracle.py:348` through the comparison gate in `engine/strata.py:60`. Their symbolic matrix determinants are a separate route from reconstructing an old marked graph field.
- **Control.** With a fresh interpreter, the ordinary double point completed the public resolver, chart verification and both zeta functions without importing SymPy. Case coverage is finite; a library call outside the profiler's named operations will not appear in the report.
